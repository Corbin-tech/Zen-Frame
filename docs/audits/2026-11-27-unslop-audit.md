# Zen Frame Unslop (code-quality) Audit — 2026-11-27

- **Produced by:** `unslop-audit` agent (report-only; no repo files modified)
- **Scope:** `src/` (29 components, 5 stores, 20 lib modules, 3 scripts, 1 layout, 3 pages) and `tests/` (79 files). Audited at `fix/close-day-focus-checkins-keys` @ `691dda7`.

## 1. Summary

The codebase is in good shape on the hard security rules (zero `x-html`/`innerHTML`/`eval` sinks outside the hash-pinned pre-paint script in `Layout.astro:30-45`; all `target="_blank"` links carry `rel="noopener noreferrer"`; no `toISOString().slice(0,10)` anywhere; no `console.log`/`debugger`/TODO/FIXME markers). The real problems are **structural, not correctness**:

- **Duplication is the dominant issue.** The same ~8 pieces of logic are re-implemented in 2–5 places each: the multi-tab `storage`-event + `savedJson` dirty-merge pattern (5 stores), the "ISO timestamp → local day key" helper (3 copies), the `"9999-12-31"` undated-sort sentinel (4 copies), the `new Date(2026, 0, 4 + day)` weekday-name trick (3 copies), hours/minutes duration formatting (4 copies), weekday-Monday offset math (2 copies), intentions sanitizing (2 copies), and Board↔taskManager search/sort "verbatim" mirrors.
- **Component bloat against the AGENTS.md extraction rule.** Six components carry 197–555-line inline `<script>` blocks of non-trivial logic (`schedule.astro` 555 lines, `Dashboard.astro` 379, `Goals.astro` 324, `Recap.astro` 315, `taskManager.astro` 301, `Board.astro` 197) — all untestable as written and all directly violating "extract non-trivial component logic into typed `.ts` modules under `src/scripts/` or `src/lib/`".
- **Dead code is small but real:** `loadSessionJson`/`saveSessionJson`/`removeSession` in `src/lib/storage.ts:44-66` are exported but used nowhere — while `pomoStore.ts:110-133` re-implements raw `sessionStorage` JSON by hand instead of using them (since fixed by PR #151).
- **Layering inversion:** `src/types/types.d.ts` contains only the `Window.Alpine` augmentation, while domain types (`Todo`, `ScheduledItem`, `Goal`, `CheckIn`, `Milestone`, …) live inside stores, and five lib modules import types *from* stores — lib → store → lib cycles by type.
- **Casing rule violated by 7 legacy components** (`darkModeToggle.astro`, `footer.astro`, `pomoTimer.astro`, `schedule.astro`, `tabs.astro`, `taskManager.astro`, `zenToDoList.astro`).
- **Tests are strong where logic lives in `.ts`**; the coverage gap is exactly where the architecture rule is violated (inline `.astro` scripts).

## 3. Top 10 highest-ROI cleanups (ranked)

1. **Extract `schedule.astro`'s 555-line script into `src/scripts/schedulePage.ts` + month helpers in `dates.ts`** — biggest rule violation, biggest untested surface.
2. **Create `src/lib/persisted.ts` and collapse the 5 copies of the storage-event/`savedJson`/merge pattern** — one fix location for all future multi-tab bugs; `tests/todoStore.test.ts:145-211` pins the behavior to keep.
3. **Single-source task sort/search in `src/lib/taskFilters.ts`** and delete Board's "verbatim" copies plus `schedule.astro:667` and `autoPlan.ts:83`'s `"9999-12-31"` — 4 copies of one sentinel.
4. **Move domain types into `src/types/`** to break the 6 lib→store type imports — unlocks the extractions above without import cycles.
5. **Extract `Goals.astro` (324 lines) and `Recap.astro` (315 lines, pure `buildSlides`)** into typed script modules — becomes unit-testable; delete the local `plural` and `weekdayName` copies while there.
6. **Dedupe date helpers in `dates.ts`**: export `dayOf`, `weekdayName`, `weekIndex`, `monthKeyOf`; delete copies in `insights.ts:31`, `Dashboard.astro:176`, `CloseDay.astro:196`, `Recap.astro:127,145`, `Insights.astro:245`, `goalsStore.ts:52`, `notifications.ts:97`.
7. **Extract `Dashboard.astro`'s 379-line script** into `src/scripts/dashboardPage.ts`; move `focusMinutesOn`/`focusMinutesIn` into `insights.ts`.
8. **Delete or adopt the dead session helpers** (PR #151 adopted them for `pomoStore`).
9. **Rename the 7 lowercase components to PascalCase + `taskDragDrop.js` → typed `.ts` + `initStores()` → `initTodosStore()`** — one mechanical PR that makes the whole tree AGENTS.md-compliant on naming.
10. **Add `tests/mergeLists.test.ts` and tests for the newly extracted modules**; fix the brittle `dueClass` string assertion in `tests/dates.test.ts`.
